# Complete 全面复核与 Squaredle 参考建议

日期：2026-10-14；基线提交 cf2a307。只验证、记录，不修改业务代码、提交或部署。

> 历史复核快照：下列五个可复现问题已在后续版本修复，并非当前待修复清单。
> 2026-10-15 验收收尾结论见 COMPLETE_ACCEPTANCE_SUMMARY.md；保留原始观察便于追溯。

## 结论

基础规则、生成题目与静态构建通过，可继续 beta；不能认定产品已完整验收。建议在正式推广前修复多标签页数据丢失、小屏溢出与交互状态问题，并改善词库覆盖。

## 可复现问题

1. P1 多标签页进度覆盖：CompleteClient.tsx:63 直接写入当前组件快照，未监听 storage 事件或合并。A/B 同时打开 REST 进度；A 找 UNDERSTAND 后，B 找 EAST；刷新 A 后 UNDERSTAND 消失，分数从 16 变成 4。修复应合并单调增长的 found/revealed 集合，监听外部变化，并增加真实多页测试。
2. P2 320px 小屏横向溢出：CompleteClient.tsx:160 grid 子项缺少 min-w-0 等约束；实测 innerWidth=320，页面 scrollWidth=324，section 右边界 323.59。棋盘/卡片向右溢出，出现横向滚动条。390px 与桌面正常。应压缩子项最小宽度、允许长路径文本换行或独立横向滚动，并回归 320/360/390/768/1280。
3. P2 点选后拖动残留旧路径：CompleteClient.tsx:106 pointerdown 直接 addTile，没有为新拖动重新建立路径。先点 E 再拖 R-S-T-A，反馈 ERSTA 而非 RSTA。混合两种操作模式需要显式状态设计，不应简单每次 pointerdown 清空而破坏点选。
4. P2 排行榜成功消息被清除：CompleteClient.tsx:151 设置提交成功后调用 loadLeaderboard；:76 在 remote=true 时立刻把消息改为空串。实际提交 Test Player/REST 成功、榜单出现，但没有持久的成功确认。应分离请求状态、榜单状态和提交回执。
5. P2 改名无法保存：score.ts:100 更新 name 受分数提升条件限制。相同/较低分请求返回成功，但名字仍旧。UI 没说明这个限制；应允许独立改名或明确响应实际保存结果。

## 产品质量差距（非路径算法错误）

- 当天板能合法连接 STAND/TANS，但有限词表不接收；浏览器输入 STAND 返回 editorial word list 拒收。可以维持有限目标词，但应将合法非目标词纳入更宽的奖金/认可词集，并确认新增词库来源。现有条件只保证有限词表的目标可连，不保证常见英语词完整。
- 难度仅依据目标数阈值：222 Gentle、109 Steady、34 Stretch；最长词分布 8～13。首日标 Gentle 却包含 UNDERSTAND/UNDERSTANDS。未评估词频、路径弯折、前后缀重叠与认知难度。
- 所有长词锚点植入固定蛇形路径，经旋转/镜像变换；熟悉后可能变成搜蛇形规律，需增加路径形状及人工选题质量。
- 键盘可以输入框输入，也能逐格聚焦选中；但棋盘没有 Backspace 撤销和 Enter 路径统一提交，用户要跨 16 个按钮 Tab。Escape 在棋盘内有效，输入框等外部焦点不会清路径。
- 无连接线，只有 tile 选中与小序号，长路径不够直观。揭词只突出格子集合，不突出访问顺序。
- 提示仅直接揭晓目标；没有逐步提示，容易由寻找退化为点按钮。揭词无确认且不可撤销。
- 词表已按字母顺序输出，未找到词的槽位也在既定位置，这相当于从一开始开放了字母序隐含提示，不是原版逐步解锁。
- 手动排行榜按钮即使后端不可用仍可点，POST 错误恢复可玩但 UI 没有真正禁用无服务提交。
- 多标签以外的数据边界：损坏存档/禁用存储有 catch；题库只校验外层 version/puzzles，不校验结构；没有完整离线或 PWA。练习回退固定第一题。

## 明确未验收/残余风险

- 未使用实体iOS/Android触控，多浏览器、屏幕阅读器、连续折线高速手势、200%文字放大、真实午夜浏览器切日、限网/离线/存储拒绝的完整浏览器测试尚缺。UTC+8边界只在单元测试验证。
- 纯静态题目答案全年公开，未承诺反作弊；reveal声明可由客户端省略。匿名cookie清除可以新增身份；10次/IP/分钟只能限制基础滥用，不是账号防刷。
- UI使用客户端日期，API使用服务器日期；设备时间错误或旧题库标签页会导致排行榜不可提交。
- 当前测试不是自动化浏览器回归套件；题目可连通测试也不能代替词库编辑质量验收。
- 没有远程数据库、线上部署或现有模式全流程回归。构建包含旧页面，但不是所有旧玩法都重新实测。

## Squaredle 值得参考的内容

从所提供 HTML/JS 的行为和界面结构确认，而不是假设后端功能本地可用：

### 高优先级

1. 分层提示：先给某格“剩余词起点数”，再给首字母/长词前两字母，最后揭晓和顺序路径。按完成度解锁，不绑定付费，避免过早放弃探索。
2. 连接线与操作反馈：明确路径顺序、退回一格、重复词和不在词库词的不同反馈；提供键盘Enter/Backspace/Esc一套一致规则。
3. 棋盘旋转：改变视角但不改变题目、答案、分数、进度。旋转需同步坐标映射，不要生成新棋盘。
4. 点击已找到词回看路径：完成后复盘特别有用，可连接本站已有单词详情，缺少详情的长词需独立合规释义方案。
5. 无剧透分享：日期、完成百分比、无提示/提示标识、奖金词数量与页面链接，不公开答案。已有主站分享能力可复用。

### 中优先级

6. 周内难度节奏与人工选题：简单日、挑战日、主题日，比当前纯目标数阈值更有复访价值。
7. 3x3 Mini：适合碎片时间和初学者；题目/进度/榜单需要独立模式标识。
8. 昨日/历史复盘与独立重玩：不能抹掉首次完成成绩，用practice命名空间。
9. 连续完成天数、个人纪录、少量有意义成就（首次无提示通关/长词突破），复用站内数据而不强制注册。
10. 奖金词数量、发现顺序/字母序切换、微型首玩引导：从实际2-3词演示开始，而不是长篇规则。

### 不建议当前加入

原广告、账号、订阅、支付、原站数据和授权字典不搬运。45度旋转、无限复杂棋盘、全局实时比较与过量成就不应先于交互稳定、词库质量和提示体系。

建议开发顺序：修复可复现缺陷 → 扩大认可词覆盖/校准难度 → 渐进提示/路径复盘/旋转 → 分享/个人记录 → Mini/历史题。不要先加会员或重后端。

## 五项缺陷修复结果

以上五项代码缺陷现已修复（本地，未部署）：

- 多标签页：规范化并合并 found/revealed 集合；写入前合并存储，监听 storage 事件并对并发旧快照重新发布并集。两页分别发现 UNDERSTAND/SAND，刷新仍保留全部四词，20 分。
- 小屏：卡片 min-w-0，路径文字可折行，操作区域可换行。320px 浏览器实测 pageWidth=305（扣除滚动条）<= viewport=320，无横向滚动。
- 混合手势：tap 保留逐格选择；首次移动到其他格时，从当前 pointerdown 起点建立独立 drag。先点 E 再拖 RSTA，反馈 RSTA 而非 ERSTA。
- 提交反馈：独立 receipt 状态，不受排行榜 GET/Refresh 清空，显示服务器实际保存的名字/最佳分/目标数。
- 同分/低分改名：SQL 始终更新名字，仅当分数/目标数提高时替换最佳成绩及其时间；响应查询实际保存结果。浏览器同分改名成功，SQLite 较低分改名仍保留最佳分。

回归：86 个攻略检查 + 9 项 Complete 测试通过；Lint、TypeScript、Next 生产构建及 Functions 打包通过；真实本地 Pages/D1 浏览器回归通过，无控制台警告/错误。其余词库/渐进提示建议与未完成的真机验收范围不变。
